# 예약 화면 호환성 수정 (2026-09-07)

DB 마이그레이션 기본값이 화면 배지에 노출되고 용인 수집은 Tailscale 인증 오류로 실행 전에 중단되어 있었다. 기존 수정은 Svelte 화면에만 적용되어 두 HTML의 예약 가능 판정도 서로 달랐다.

- 공통 판정 원본: `Pages/shared/reservation-policy.js`.
- `Pages/index.html`, `PagesCourtIssum/index.html`, Svelte `src/lib/courts.js`가 같은 원본을 사용한다. `node scripts/sync-reservation-policy.js`로 독립 배포용 사본을 만들고 `--check`로 일치 여부를 검증한다.
- 확인된 유형만 배지로 표시한다. 미확인·조회 실패·오래된 정보는 잔여 없음과 구분하고 가능 수량에서 제외한다. 유형 정보를 제공하지 않는 다른 도시에는 용인 전용 메타데이터 검증을 강제하지 않는다.
- 동일 코트·시간을 묶어도 각 예약 유형의 원본 링크와 실제 표시 슬롯의 확인 시각을 보존한다. 수원의 시작 시각만 있는 응답도 지원한다.
- 배포 workflow는 두 HTML의 동작 테스트와 Svelte 검사·빌드를 실행하고 `courtissum`과 `search-tennis-court`를 함께 배포한다.

용인 수집기는 `not_open` 및 정규화된 예약 유형을 보존하고 `접수대기`를 처리하도록 수정했다. Tailscale 연결 실패 시 직접 수집을 시도한다. 인증정보는 변경하지 않았다.

운영 데이터 복구: 원문 재수집으로 68개 상품과 1,771개 성공 날짜를 갱신했다. 구민우선 20개는 접수 대기, 일반예약 48개는 접수중이다. 시민우선 상품은 해당 조회 시점의 목록에 없었다. 실패 날짜 1건은 기존 원본을 보존하면서 예약 가능에서 제외했다. 이 복구 과정에서 알림은 발송하지 않았다.

검증: 공통 정책·경계 사례·두 HTML 실행 기반·기존 예약 정확도 테스트 통과. Svelte 검사 오류/경고 0, 빌드 통과. 실제 RPC를 이용한 브라우저에서 일반예약 표시와 구민우선 접수대기 필터를 확인했다.
